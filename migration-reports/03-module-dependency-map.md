## Known ownership boundaries

- **Identity/session**: fully owned by WPA Central Auth (`wpa_auth_api`). Not modified, not reimplemented — `furtail_app_api` only validates its tokens and bridges to a local user record.
- **Payment processing**: the actual downstream payment gateway integration was not inspected in this step (server-internal to `furtail_api`, outside `D:\wpa\furtail`'s Flutter/legacy-API pair as directly observed). `furtail_app_api` will need its own decision here — recorded as UNKNOWN, not assumed to be a simple lift-and-shift.
- **BPA backend**: referenced only in `furtail_api`'s own `.env.example` comments as a consumer of Furtail data via a legacy audience token. Its scope, endpoints, and whether it touches `furtail_app_api` in the future is UNKNOWN — not inspected, outside this audit's file scope.
- **Push notification delivery (FCM)**: owned by Firebase, both today and presumably in the new API — not something `furtail_app_api` would reimplement, only integrate with.
- **Media storage (MinIO)**: infrastructure-owned, not application-owned — a deployment/ops decision for Step 4+, not a module-design decision.
