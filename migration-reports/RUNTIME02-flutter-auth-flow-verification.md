## Authentication Flow Summary

### Architecture
```
Flutter App (10.0.2.2:7300)
    ↓
Furtail API (localhost:7300)
    ↓
JWT Verification (HS256, Central Auth subject)
    ↓
JIT User Provisioning
    ↓
PostgreSQL (localhost:5433)
    ↓
User, UserCentralAuthLink, UserAuth, UserProfile
```

### Token Flow
```
1. User enters credentials (admin@wpa.com / Password123!)
2. Central Auth issues HS256 access token
   - Claim: sub = cmr0jp6b... (Central Auth subject)
   - Claim: aud = furtail-mobile
   - Claim: iss = http://localhost:5010
3. Furtail API receives Bearer token
4. JWT verifier validates signature (HS256 HMAC)
5. getOrProvisionUser() called with authenticated principal
6. JIT provisioning creates:
   - User (id=7)
   - UserCentralAuthLink (subject → userId)
   - UserAuth (email=admin@wpa.com, provider=CENTRAL_AUTH)
   - UserProfile (username=generated, displayName=email)
7. /auth/me returns 200 with user profile
8. Flutter stores token and navigates to home
```

### Idempotency Guarantee
```
Second login with same account:
- JIT lookup by subject succeeds
- Existing user returned (id=7)
- No duplicate records created
- Database counts remain 1, 1, 1, 1
```
